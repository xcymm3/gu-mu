# 剧情分页规则

一页承载一小段完整意思，宁可留白，不把下一句的半句话塞入当前页。

- 作者段落（空行）、不同说话人和演出事件不跨页合并。常规一页最多两个完整句子；成对引用与附属说明优先保持完整。
- `pagination.ts` 负责语句边界、降级规则与原文偏移，不依赖屏幕固定字数。
- `useDialoguePagination` 使用不可交互、对辅助技术隐藏的测量节点，按真实对话框宽高、字体、行高、强调词样式判断容量；字体加载、样式变化和窗口变化会重新测量。
- 正常情况下只在完整句子之间分页。只有单句在空页仍放不下时，才依次使用分号、逗号/冒号、空白、Unicode 字素边界保底。引号和句末标点不独自成为下一页；原文不被改写。
- 极端小窗口若连一个字素及其标点都无法容纳，算法仍保留该文本，不删除内容；正常支持尺寸通过浏览器溢出检查约束。
- 正文、选项结果、战斗结算共享同一规则。战斗开始按钮预留空间保持稳定，避免最后一页出现按钮后反复重新分页。

## 阅读位置与旧存档

新存档在原有版本 6 格式中增加可选 `narrative.anchor: { beatIndex, offset }`，定位原文而非屏幕相关的页码。原有字段和存储键不变。阅读栏点击「存读档」或按 S 可直接存入或读取六个槽位；覆盖前需要确认。旧快速存档在同一界面作为「旧版存档」只读保留，不覆盖普通槽位。

旋转或改变字体后，显示包含该锚点的页面；必要时会重现该页前面的少量文字，不跳过后文。旧存档没有锚点时保留角色、旗标、路线、战斗等游戏状态，从当前场景开头重读，不能将旧算法的页码误当新页码。

安装过的离线 APK/EXE 不会随源码更新自动变化，需重新构建安装包。存档兼容性不改变 Android 覆盖安装必须使用相同签名的要求。

## 验证

`pnpm test` 包含语句/标点、超长句、字素无损、全文遍历和锚点测试；`pnpm test:e2e:run tests/e2e/pagination.spec.ts` 覆盖桌面与手机横屏、实际溢出、完整开局、选项结果、字体变化、旋转和存读档。
