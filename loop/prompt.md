# 目标

在本次全新 Codex CLI 上下文中，为《血蛊引》两小时受控改进 Loop 完成一个可验证任务。最终目标是：全部正式路线可自动试玩，关键存读档与战斗路径可重复验证，剧情因果与人物表达通顺，美术风格统一且适配目标视口，构建、测试、依赖审计和浏览器控制台没有已知阻断问题。

# 必须遵守的工作流

1. 检查 Git 状态、当前分支与最近提交，保留用户和其他任务的无关改动。
2. 只处理监督器指定的一个任务；除最终集成任务外，不顺带开启其他任务。
3. 先建立可复现的失败证据或验收基线，再做满足验收条件的最小连贯修改。
4. 代码、剧情、美术和测试必须使用现有架构边界；不得把路线判断或大段剧情重新硬编码进 React 组件。
5. 任务完成前运行任务专用检查与 `pnpm verify:fast`。涉及浏览器、美术、存档、可访问性或最终集成时必须运行 `pnpm verify`。
6. 只有所有验收条件都有命令、截图或测试证据时，才把该任务改为 `done`，更新 `updatedAt`，并在 `loop/progress.md` 追加简洁证据。
7. 使用一次 Conventional Commit 提交该任务，格式为 `<英文小写 type>: <具体简体中文摘要>`，主题末尾不加句号。确认不包含无关改动后推送当前专用分支；首次推送使用 `git push -u origin automation/art-playtest-loop` 建立 upstream，禁止强推和改写历史。
8. 验证或推送失败时不得标记完成。记录完整命令、退出码、关键错误和下一假设；连续失败时缩小问题、增加回归测试或标记 `blocked`。
9. 只有全部任务完成、`pnpm verify` 与 `pnpm audit --prod --registry=https://registry.npmjs.org` 均通过时，才创建 `DONE.md`。

# 自动试玩标准

- 自动试玩必须使用真实浏览器流程验证主菜单、身份选择、正文推进、选择、战斗、历史、设置、手动存档、快速存档、读取与结局。
- 覆盖四条正式路线、三种身份的有效组合、所有登记结局以及关键胜败分支；随机行为必须可注入或固定种子，失败可复现。
- 不得通过只在测试中强行写最终状态来冒充通关。允许使用测试专用驱动减少等待，但必须经过与玩家相同的公开动作或游戏引擎入口。
- 页面错误、未处理 Promise、失败资源请求和 React 控制台错误必须作为失败。
- 桌面至少验证 1280×720、1366×768、1920×1080；移动验证 390×844 竖屏提示和对应横屏舞台。

# 美术标准

- 先截图再判断，不得只读 CSS 就宣称美术合理。对主菜单、身份选择、普通对白、多人物对白、三选项、战斗、历史、设置、存档和结局页保留可复现截图证据。
- 优先修复占位资源、人物与背景风格不一致、遮挡、裁切、对比度、焦点层级、长文本溢出和小屏安全区问题。
- 需要创建或编辑位图时，使用当前环境可用的图像生成/编辑技能；不得用脚本伪造生成图，也不得引入来源不明或受版权保护的素材。
- 资源使用 WebP 或更合适的网页格式，保持透明边缘、合理尺寸和现有资源预算；修改后验证加载失败回退。
- Hallmark 样式声明必须与实际实现一致；直接颜色值、`100vw` 溢出和虚假的 pass 标记应被修正或诚实降级。

# 剧情标准

- 按路线逐节点检查人物动机、信息来源、空间位置、伤势、道具、旗标、战斗结果与下一节点的因果连续性。
- 保持角色口吻和既定世界观术语；删除重复解释、突兀转折、无前置认知和与状态冲突的描述。
- 不为“更文艺”而整线重写。每次文本修改都必须指向具体问题，并由路线连通、关键词合同或针对性测试保护。
- 文档、图鉴数量、版本号和实际代码必须一致。

# 边界

- 只写当前仓库和专用工作分支，不部署、不发布、不合并 `master`。
- 不添加遥测、账号、付费 API 或秘密信息。
- 不删除现有剧情、路线、结局或用户资源，除非当前任务验收明确要求且有回归证据。
- 不把“测试通过”等同于绝对无缺陷；最终结论必须列出覆盖范围与剩余风险。
